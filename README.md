Консольная утилита для сжатия и декомпрессии файлов и директорий с использованием алгоритма RLE (Run-Length Encoding), также известного как метод «стопка книг». Проект разработан в рамках <b><i>курсовой работы</i></b> по дисциплине «Основы программирования» 🎓.

Скачать готовую программу можно в разделе [*Releases*](https://github.com/n1xsi/rle-compressor/releases/tag/v1.0.0).

## 🛠 Установка и сборка

Для сборки проекта требуется компилятор `gcc`.

### 🐧 Linux / macOS
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/n1xsi/rle-compressor.git
   cd rle-compressor
   ```
2. Соберите проект через `make`:
   ```bash
   make
   ```

### 🪟 Windows
1. Установите MinGW (или любой другой порт GCC для Windows).
2. Откройте командную строку (CMD) или PowerShell в папке проекта.
3. Скомпилируйте вручную (или используйте `make`, если он установлен, или скомпилируете через vscode):
   ```cmd
   gcc src/main.c -o rle.exe
   ```

## 🚀 Использование

### Синтаксис
```bash
# Linux/macOS
./rle <команда> <пути...>

# Windows (CMD/PowerShell)
rle.exe <команда> <пути...>
```

### Команды
- `compress` — сжать файл(ы) или директорию.
- `decompress` — распаковать архив `.rle`.

### Примеры

**1. Сжатие одного файла:**
```bash
./rle compress file.txt
```
*Создаст архив `file.rle`.*

<br>

**2. Сжатие директории:**
```bash
./rle compress my_folder
```
*Создаст `my_folder.rle`, содержащий все вложенные файлы.*

<br>

**3. Сжатие группы файлов:**
```bash
./rle compress data1.bin data2.log
```
*Создаст единый архив `compressed.rle`.*

<br>

**4. Распаковка:**
```bash
./rle decompress archive.rle
```
*Восстановит исходную структуру файлов в текущей папке.*

## 🧠 Описание алгоритма

Программа использует вариацию RLE:
1. Читается поток байтов.
2. Подсчитывается количество последовательных одинаковых байтов (**МАКСИМУМ** до 255).
3. В выходной файл записывается пара: `[количество (1 байт)][значение (1 байт)]`.

Для архивации директорий используется кастомный контейнер:
`[Путь файла (256 байт)] [Размер сжатых данных (size_t)] [Сжатые данные]`

## 📊 Эффективность и применимость

Данная реализация RLE эффективна для данных с **низкой энтропией** (высокой предсказуемостью). Из-за отсутствия режима "литералов" (записи без сжатия) на каждый уникальный символ тратится 2 байта.

### ✅ Где алгоритм эффективен:
*   **BMP-изображения и графика:** простые рисунки с большими областями одного цвета.
*   **Системные логи и данные датчиков:** файлы, где значения часто повторяются или меняются редко.
*   **Разреженные файлы:** файлы, содержащие большие последовательности нулей (padding).
    *   *Пример:* `00 00 00 00 00` (5 байт) -> `[5][0]` (2 байта). **Сжатие в 2.5 раза.**

### ❌ Где алгоритм неэффективен:
*   **Художественный текст:** в естественном языке буквы редко повторяются подряд.
*   **Сжатые данные:** JPEG, PNG, ZIP архивы (они уже имеют высокую энтропию).
*   **Случайные данные:**
    *   *Пример:* `A B C D E` (5 байт) -> `[1]A [1]B [1]C [1]D [1]E` (10 байт). **Увеличение размера в 2 раза.**
